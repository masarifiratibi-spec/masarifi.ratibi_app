# Finite T03 QA consumer — local preparation

This is a disabled, bounded QA-session consumer. The general operations worker stays off. It is not a scheduler or a repair of general staging sync availability. No hosted installation, claim or phone acceptance has been performed by the implementer.

The six declared phases reconcile the original approved warm mutation, restore the original exact NULL note, exercise a fresh final-candidate warm offline Save/restart/reconnect, restore NULL, exercise a cold-local edit/reconnect, and restore NULL. The consumer discovers later operation IDs automatically only for the bound owner/device/resource, exact next note, first attempt, matching base version and unchanged financial/posting state. At most six first-time queued claims and one in flight are allowed. Direct ordinary PATCH restorations can reduce the claim count.

`session.template.json` deliberately lacks private identities, current catalog/function/source pins, deadline and reviewed package pin. It cannot execute. Generate a private mode0600 manifest only through the reviewed root-side binding procedure; customer rows, IDs, payloads and credentials must never enter tracked evidence or terminal output.

## Connections and execution

`host_broker.py` is the Linux host reader/launcher. It opens the approved worker/API/migration files separately through no-follow directory/file handles, verifies exact owner/group/mode/size/stability and independent file hashes, and sends a bounded private stdin frame. It never shell-sources files or places credentials in arguments, Docker environment, mounts, logs or evidence. Both child output streams are privately bounded; unexpected failures emit sanitized codes only. The former standalone `host_reader.py` is retained as local history and is not shipped or invoked.

Worker and API files are independently parsed and validated into separate normal configurations. The worker pool owns claim/completion/retry/conflict creation; the separate API command pool owns ordinary ledger/security/reference policy and conflict-target reads. Both configurations are validated before pool allocation, and both pools are closed even if one close fails. The bootstrap URL exists only in a deferred separate `pg.Client`. The existing verified `sslmode=verify-full`, exact `NODE_EXTRA_CA_CERTS` setting, CA file bytes and role identities remain mandatory. No SSL override, access grant, auth refresh or owner-principal substitution is provided.

Each operation uses one protocol: a dedicated global reader begins REPEATABLE READ READ ONLY, verifies target/provenance/global exact pending set/resource, and exports its snapshot. An already worker-role-bound checked-out ordinary client begins RR READ WRITE and immediately imports that server-generated snapshot before any query. It verifies role/endpoint/snapshot/claim capability, calls the pinned existing claim function with limit1, validates the whole transition, and commits. The exporter remains held through acknowledged worker claim commit. Only an acknowledged commit reaches the shared normal executor. Any uncertain commit, retry, reject, conflict, lease loss or state/receipt mismatch stops the session without another attempt.

The journal uses exclusive mode0600 sequential records in a mode0700 owned directory, fsyncs bindings and consumed budget before claim, and never overwrites an earlier record. A hash/sequence completion marker appears only after state-file and parent fsync. Status accepts only that committed chain; a partial/missing marker is not a verified phase. An existing session journal blocks another invocation; restart cannot reset phase or budget. Uncertain inflight bindings remain available for independent reconciliation.

A binding that has reached durable storage counts as the one in-flight operation. If a stop signal or deadline arrives during that handoff, that single bound claim may finish through the normal bounded query/lease path before the session stops. No additional operation is bound after the stop/deadline check; this is bounded in-flight grace, not an automatic retry.

An applied mutation receipt plus authoritative expected version/note and unchanged financial/posting fingerprint is required after execution. `processed-once` alone never advances a phase. A direct cleanup instead requires a new completed correlated ledger API idempotency receipt plus the same authoritative checks; no cleanup or receipt is manufactured.

## Ordered operational artifacts

1. `transport.cjs` prepares a deterministic regular-file tar.gz plus one UTF8/LF `.txt` JSON array of ordered upload commands. Every command is at most64KiB; chunks carry exact sequence/bytes/SHA. The decoded Python program is hashed before execution, and the completed archive's exact bytes/SHA are checked before upload success. Upload does not extract or start anything.
2. A separate public install command verifies the archive and package pins, bounds expansion/member sizes, rejects unsafe paths/links/special/duplicate members, and exclusively writes read-only public files. No existing package or service is overwritten.
3. `package-only` uses the existing digest with network none, no private input/CA/journal mounts and Docker logging none. The real image must match every required dependency file/resolution. A mismatch reports only a safe public module path/code and stops; no fallback/install occurs.
4. `inspect` uses three private original config channels and bounded read-only transactions. It returns only metadata to a private0600 host file: actual Node-client search_path, SQL-json catalog SHA, the fixed17-relation/45-function contracts, columns/defaults/ACL/RLS/policies/triggers/rules/index state, plus successful initial QA/role/capability predicates. No claim occurs. Those exact expectation bytes need independent review; `approve-inspection` requires their explicit reviewed SHA and creates a separate approved file.

   The public receipt reports the raw-file SHA and a canonical SHA of that same complete inspection object, including scope, host IDs, searchPath and TimeZone. Canonical keys follow the existing JS UTF-16 order recursively, preserve array order and use compact UTF8 JSON; no contract field is omitted or normalized away. Root/Astra independently reconstruct the metadata in one read-only repeatable-read snapshot under those reported context settings. Approval requires both independently reviewed pins, rereads the protected file, verifies both and enabled=false, then exclusively writes enabled expectations. No credential, mutation/resource row or private binding is included in this inspection object.

5. `bind` compares those independently reviewed expectations before deriving the existing JS-canonical provenance hash from that same verified snapshot. It verifies the unchanged original SQL-row/resource anchors, exact global pending set, due eligibility, expense/no-linked-salary predicates and full ordinary-role preflight. Private output contains bindings/hashes, never raw credential URLs. The broker exclusively writes an FD, binds owner/group1000 and mode0600, verifies identity and fsyncs file plus parent. Binding does not claim.
6. `preflight` requires the exact private-manifest SHA and saves a package/archive/manifest-bound zero-claim receipt. `session` requires that receipt and runs the six phases automatically. The idle poll is5000ms. Its deadline is set near actual binding/start, never during package preparation. All credential containers have logging none, read-only root/artifact/CA, no ports/capabilities, nonroot user, bounded resources, restart no and an exact persisted identity before start. Only the session journal is writable.
7. `status` verifies the exact owned container, manifest and committed journal chain, returning only phase, consumed claims, running/completed/stopped status, expected QA note marker and version. Wait for the persisted phase and ordinary app receipt before another phone edit. `stop` targets only the exact recorded identity and hardening; it does not discover/adopt another container. Public launch commands name the run ID in advance, so status/stop remain usable if the terminal closes. The broker ignores terminal hangup for the finite session; an independent in-container deadline plus120s grace bounds a broker failure. Expiry during a command leaves an uncertain durable binding for review and never retries it.

`public-host-actions.json` contains concrete package-only/inspect commands and disabled later-phase prerequisites. Later commands are generated only after independent inspection/manifest pins exist. All wrappers hash the program before exec. No generated public transport/action artifact contains env values, customer rows or private bindings.

Read-only failures use the shared reviewed diagnostic-codes.json: configuration, connection, identity, catalog, function-contract, candidate and runtime-preflight phases; exact guard literals and an explicit SQLSTATE allowlist. Both sanitizers preserve the same approved tuple and discard messages, SQL, stderr, rows and unknown fields. The broker exclusively saves that tuple to the owned run's failure.json before cleanup; no raw stream is persisted. Non-inspect runtime/candidate phases and connection-cleanup failures are attributed separately. Package qualification is immutable per full64-character package pin, with the same named receipt used for write/read; earlier package receipts are preserved and cannot qualify another package.
