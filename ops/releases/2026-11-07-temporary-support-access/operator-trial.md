# Operator acceptance window

Use this worksheet only after the specific packet is approved. It records what the operator must observe; a completed worksheet is not itself authorization or authentication.

Before staging either candidate, arrange simultaneous availability of the existing account owner, assigned support operator, and a reviewer authorized independently of the requester. Use only operator-owned qualification accounts and legitimately held roles. Confirm the revoker and negative-case actors are available; do not create roles, impersonate a customer, use production records or extract a session token. If the actors cannot participate, defer the switch. The 15-minute ticket starts when candidates are staged. Leave time for independent review and rollback.

1. Record the ticket, both candidate IDs, approved manifest digest and switch observation privately. Confirm the served Admin build and the four anonymous GET results: Admin collection/detail 401/401; owner collection/detail 401/404. All four must carry exactly one no-store header. Direct and public status must agree. Verify default/primary and the original specialized endpoints remain unchanged.
2. In the named case, create and read back one status-only request. Record its opaque digest and version. Replay the same authorized body and idempotency key after an uncertain response and compare both receipts. Bind the primary lifecycle to this same request. A historical pending request alone does not establish a fresh grant.
3. Only the actual owner completes recent authentication and consents. Verify the requester cannot act as their own reviewer. A different legitimate reviewer approves using the current version; a stale decision must fail without changing that version. The assigned operator sees only the masked account-status projection, retains their session after refresh/back, and successfully ends the grant. Read back the terminal state.
4. Use independent, explicitly authorized status-only cases for natural expiry and external revocation. The API accepts durations of 5–60 minutes; start the 5-minute expiry case early in the trial. Confirm denial and removal of workspace data after expiry or revocation. Use separately authorized qualification actors for wrong-owner and wrong-assignee denials. Never adjust the service clock, database rows, permissions or customer accounts to force an outcome.
5. Keep raw observations in the private evidence directory only. Bind each case in `acceptance_receipt.CASES` to its actual actor, request, observed HTTP result, version and observation time. The operator independently checks that each digest describes the corresponding real observation. Persist the route only when the complete evidence is verified and the watchdog acknowledges acceptance. If any case or actor is missing or time runs short, abort and prove restoration. Keep original services and sessions available.
