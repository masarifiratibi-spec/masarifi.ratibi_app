# Forward-only outbox publication on the current VPS

The dedicated container `masarifi-outbox-forward-20261120` runs `platform.outbox.dispatch` through the scoped operations scheduler. Its only network is the internal self-hosted database network. It has no HTTP listener. Runtime files are mounted read-only from `/opt/masarifi/selfhost/releases/2026-11-20-outbox`. The worker uses the pinned application image and the same verified PostgreSQL endpoint and worker role as the import worker. The application and other workers continue in their own containers.

The production boundary in the root-owned `cutoff` file is **2026-11-19T22:05:49.976Z**. Retain this exact value across replacement and reboot. Eligibility requires an immutable creation timestamp strictly after this boundary, independently of retry times. The partial index `private.outbox_forward_due_20261120` on `(available_at, id)` covers unpublished rows created after 2026-11-19T22:03:24.000Z. The query applies the later activation time. Both predicates are necessary for the intended scope and efficient indexed selection.

The publisher locks up to 16 due event rows with `SKIP LOCKED`, builds envelopes through the pinned API validator, and sends each message and marks its event published in the same PostgreSQL transaction. It uses the actual typed application queue publisher. Validation failures retain the new event with a retry time. The standard scheduler remains responsible for job history and leases. Customer-facing handlers and downstream queue consumers are outside this process.

## Operating the release

- Read current status with `docker inspect -f '{{.State.Status}} {{.RestartCount}}' masarifi-outbox-forward-20261120`. Compare successful runs for this job with counts of new distinct event IDs in PGMQ and due, unpublished rows after the activation time. A successful job writes its own audit event, which normally waits for the next interval.
- To pause, run `docker update --restart=no masarifi-outbox-forward-20261120` then `docker stop -t 30 masarifi-outbox-forward-20261120`. This preserves queued messages, historical rows, the activation time, and the index.
- To resume the existing container, verify the activation time and database identity, run `docker start masarifi-outbox-forward-20261120` and restore `docker update --restart=unless-stopped masarifi-outbox-forward-20261120`. Recreating the container for a new application image requires requalifying its scheduler, envelope builder and queue publisher.
- `python3 launch.py test` runs rollback, old-row exclusion, malformed-payload retry, envelope redaction, duplicate prevention after a successful commit, and job-scope tests in connection-local temporary tables. The test replaces the PGMQ send with an insert into a temporary queue. `python3 launch.py check` verifies the production database role and index without starting a publisher. Both commands run on the VPS from the installed release directory.
- The legacy general-purpose worker and its backlog were left in their previous state. Its existing unfiltered claim function can select historical events. Keep worker launches scoped when preserving the historical backlog. The internal PGMQ destination accumulates messages until a consumer acknowledges them. This release implements publication only.
