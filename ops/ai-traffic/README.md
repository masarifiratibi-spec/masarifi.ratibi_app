# AI traffic rollout

Ship the API and every assistant and voice worker together. The migration uses the existing PostgreSQL database for cross-process admission. It requires no Redis service. Existing daily quotas, cost accounting and provider attempt policies still apply. Older mobile builds continue to use their existing error handling.

1. Match the effective JavaScript on the host (including bind mounts) and the worker entry points to the candidate's base. Build the reviewed delta on the effective release. Save the previous image, container launch definitions and NGINX configuration for rollback. Use the normal migration runner and checksum manifest.
2. Set `MASARIFI_AI_TRAFFIC_MODE=shadow` on the API and workers. On the API set `MASARIFI_AI_TRUSTED_PROXY_IP` to the verified socket peer of the restricted NGINX ingress. NGINX must overwrite `X-Real-IP` with its validated client address. Check two distinct client networks before interpreting IP limits.
3. Include `nginx-http.conf` in the http context and `nginx-server.conf` in the production API TLS server. Verify effective location inheritance, current proxy timeouts and real-IP configuration with `nginx -T`, validate with `nginx -t`, then reload. The edge defaults to dry run. Verify readiness, one normal chat, one recording through processing and the result readers on the deployed versions.
4. Compare 24–48 hours of shadow logs with normal traffic, including users behind a shared carrier IP. Compare AI_TRAFFIC_LIMITED by operation and lane, AI_QUEUE_LIMITED, AI_PROCESSING_LIMITED, database failures, API latency, queue age and completed operations. The shadow mode allows over-limit requests to complete. Check ingress dry-run rejections in the NGINX log. Ship the mobile cooldown handling before enabling rejection where possible.
5. When the observation supports enforcement, set the API and workers to `enforce` and set both NGINX dry-run directives to `off`. Verify the running configuration, continued ordinary use and HTTP 429 with Retry-After. Check the release on both platforms. Roll back to shadow to stop rejecting while preserving measurements, or use `off` and remove the NGINX includes to disable the feature. No data migration reversal is needed.
