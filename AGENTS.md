# Masarifi project instructions

Use [the maintained project guide](docs/project/README.md) for current architecture, platforms and evidence. Use `codex/voice-promoted-operating-2026-10-13` as the primary source for shared architecture, features, API, Admin, data and agent rules. Use `codex/google-play-release-2026-11-24` for Google Play differences and `iOS` for Apple differences. Check branch and upstream before editing. Implement shared behavior on the operating base, then carry the scoped change to both release lines or verify an existing equivalent there. Record the source commit and test result per branch. A shared change remains pending on any line without that evidence. Consult the [AI handoff](docs/project/ai-handoff-ar.md) and its release comparison before updating a divergent file. Keep platform-specific changes on their release line.

Read the app constitution for domain rules. Name the commit and environment when reporting verification. Use live adapters in configured production profiles and fixtures only in their explicit demo/test modes. Enforce owner and staff permissions on the server. Use a disposable database for migration tests.

For old specs, release packets, command templates and runbooks, check the date, source pin and target in [the audit](docs/project/audit.md) first. A recorded production action is evidence for that release. CI or signing changes need their own review against the actual workflow conditions.
