# Account deletion reliability

Use the existing worktree and branch. User authorization waives routine approval gates; no actual owner sign-out/deletion, Production mutation, device operation, or worker replacement belongs to this slice.

## Diagnosed causes

- Identity deletion updates `status='deleted'` without `deleted_at`, violating `profiles_deleted_at_check`; the worker lacks column update privilege.
- Only locally registered device sessions are revoked although `ClerkClientService.revokeUserSessions` already enumerates provider sessions.
- Mobile discards cooling-off/completion/version fields and maps both verified and completed to accepted. Security settings never renders mutation errors or results.
- Clerk Expo 4.6.5 locally exposes session `startVerification`, `prepareFirstFactorVerification`, and `attemptFirstFactorVerification`; use these against the current session, fenced by owner and session IDs, with an explicitly refreshed token after successful verification.
- Reconciliation already preserves non-active profile tombstones. Keep the immutable deleted profile subject to prevent resurrection. SPEC-BE-003 User Story 7 permits retained PII only under an active policy/hold; no registered policy requires retaining a live Clerk user. Delete the external identity after the tombstone, with idempotent 404 handling and retryable provider failure.

4. Add an authenticated deletion panel with confirmation, actionable safe errors, pending progress, fresh-auth code verification/retry, status refresh and cooling-off cancellation. Reuse the panel from security and privacy settings. Tests exercise visible outcomes, SDK and HTTP boundaries only.
5. Run focused RED→GREEN tests, mobile/API typechecks and scoped lint; inspect the whole diff with test-guard and clean-code-guard. Root coordinates full suites, migrations, isolated DEV worker deployment and disposable-account native evidence.
