# Grounded assistant response layout

The user approved the conversational mockup and explicitly requested implementation: a prominent expense amount, a readable comparison, one brief explanation and a practical saving suggestion based on actual records. Keep Saudi Arabic and intentional English, existing theme, RTL/LTR, privacy masking and exact currencies.

The chosen approach is a typed presentation generated by the server from authenticated successful summary reads, carried in existing optional message metadata and rendered by the mobile bubble. Plain prose remains the compatible fallback for other questions and older messages. Styling Markdown or extracting monetary totals from generated prose would not establish financial meaning; enabling the existing fixture-only card would publish invented data. Neither is used.

Only answers whose grounded monetary references identify confirmed expense summaries qualify. Mixed income/balance/transaction questions retain their complete answer. Each currency remains independent. Comparisons reuse exact BigInt calculations and matching account/category/search filters. A month-to-date summary may read the matching previous calendar-month interval through the existing authenticated summary tool; no new model call, scope or quota is introduced by that read.

Explanation may describe an actual matched category change, never infer its cause. Missing categories in a capped top-category list are not zero. A quantified saving goal is conditional on returning an increased category to its observed previous level; it is an illustrative target based on those records, never a guarantee or a saved budget. Without a comparable baseline, provide a short review suggestion tied to an observed category and omit a monetary saving goal. Unavailable sources must be distinguished from empty successful aggregates.

The UI puts the exact amount and currency first, followed by dated comparison and brief explanatory/saving sections. The original grounded answer remains unchanged in storage and accessible through More details; unsupported counts, mixed scopes or gross/net meanings retain the ordinary complete answer. Long amounts wrap, support large text and remain readable in dark mode. Privacy reveal masks the entire financial presentation until explicitly revealed. Preserve action review, feedback, old messages and local drafts.

No financial writes, capture permissions, PDF/ZIP/Feedback replay, credential changes, old provider-scope replay, migration, merge or Production. New live provider acceptance requires its own bounded scope; local tests and runtime preparation proceed independently.
