## Tested correction

Candidate migration: [outbox_voice_confirmation_lookup_index.sql](../../../supabase/migrations/20261101223723_outbox_voice_confirmation_lookup_index.sql). It adds only:

create index outbox_events_voice_confirmation_idx
  on private.outbox_events (aggregate_id, created_at, id)

## Cleanup and relationship decisions

Unpublished events are durable pending work. Age and an operations prefix do not establish that they may be discarded. Replaying them with an unrestricted replacement worker is also unsafe. First reconcile their consumer contracts, retry/idempotency state, whether operations-history events have any remaining recipient, and an archival/retention policy. Export and verify eligible terminal history before bounded deletion. Do not mark events published, truncate Outbox, delete users/financial data, shorten idempotency windows, delete Storage metadata directly, or run VACUUM FULL/blanket REINDEX to make the dashboard look smaller.

A conservative restored-catalog check produced121 foreign-key index review candidates. It excludes partial indexes and does not prove121 defects: many relationships are tiny, partly indexed or intentionally covered differently. Existing owner-composite keys are security boundaries and remain unchanged. Rank candidates using live relation sizes, actual read/delete/update plans and benefits versus index space/write cost before adding indexes. Security/performance advisor calls failed their project-user admission checks, so no clean-advisor result is claimed.
