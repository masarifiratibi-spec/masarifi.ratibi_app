## PERF01 implementation status

The source now records fixed startup boundaries, HTTP token/body/schema durations, and Home/Accounts/Transactions/Reports screen milestones. Child transaction summary readiness is observed through the existing query cache without creating a second request. Tap attempts are recorded before mount; superseded/expired attempts remain failures rather than disappearing from statistics.

Offline/plain-array provenance uses an ephemeral WeakMap without changing payload identity, wire schema or persisted data. Derived Home summaries retain known provenance. An affirmative remote marker comes only from successful, non-aborted shared HTTP decoding/validation; there is no inferred remote marker at an arbitrary service return. Unknown or structurally shared results whose provenance is lost remain conservatively cached. Their refreshed-data acceptance is **unqualified**, even if timestamps look recent. Future timestamps and placeholder data cannot qualify refresh.

`interactive` means a focused, current-owner/scope, usable-data/layout observation followed by two JavaScript animation callbacks. It is not physical display presentation or independently verified touch responsiveness. `visible` is a positive content layout after the existing startup cover releases; overlays and physical presentation require separate device evidence. Route intent coverage is explicit: tab selection, reports header, More→Accounts and Manage Accounts. Uninstrumented entrypoints are mount-origin observations and cannot qualify tap latency.

All diagnostic output uses the existing400-event-per-process cap and fixed enums/numbers. A collector must reject truncated/incomplete attempts, preserve errors and start-without-terminal outcomes, and limit navigation batches to the event budget. Timings describe work including failure where no success outcome is available; they do not prove a successful request. Raw request/financial/auth content is never added to these records.

Functional/source qualification, immutable diagnostic artifact preparation, device diagnostics and comparable plain-artifact acceptance remain separate gates.
