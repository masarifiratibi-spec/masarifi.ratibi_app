# Inherited Mobile dependency exposure — 2026-10-04

Assessment baseline: frozen Voice candidate `397677423b9336722bc9af2405f1a5b1d7b3a623`, followed by the narrowly authorized native-link mitigation based on `deb6611`. Dependencies and authentication remain unchanged. This is an exposure assessment, not a claim that all dependency advisories are remediated.

`npm audit --omit=dev` reported 43 high and 22 moderate **affected package nodes**, representing eight distinct upstream advisory URLs; many parent packages inherit the same transitive finding. No critical finding was reported. The production Android Expo export succeeded with source maps: 2,068 bundled Metro modules / 2,075 mapped sources. Exact `/node_modules/<package>/` matching avoids mistaking Expo's own UUID implementation for the vulnerable npm `uuid` package.

Correction after tracing the installed Expo Router 55 source: its `getLinkingConfig` supplies the Router fork of `getStateFromPath`, whose `parseQueryParams` uses `URLSearchParams`. React Navigation's base parser still imports `query-string`, and Router uses that package for query serialization, explaining the bundled decoder. The earlier claim that this native inbound path directly reached `queryString.parse` was not supported by the installed implementation. A contained child-process control still demonstrates the package defect: `query-string.parse('label=' + '%C0'.repeat(2000))` exceeds a two-second bound and is terminated. This establishes vulnerable package behavior, not a device exploit or proven use of the base parser by this app.

The `+native-intent` hook now validates the raw URI with built-in `decodeURI` and invokes the installed Router's extraction before returning unrelated links to navigation. Invalid raw UTF-8, incomplete escapes, and nested values that cause an actual extraction error return `/`; original sensitive link text is neither logged nor persisted. The installed extraction helper is standalone and uses URL/built-in decoders, avoiding the vulnerable fallback. Cold/live Router integration tests exercise this boundary through actual navigation parsing. Valid Arabic and literal percent parameters remain intact: `label=100%2525` produces the existing Router parameter `100%`. Deeper nested malformed values/keys that the Router safely handles with `URLSearchParams` keep their existing behavior; the guard adds no extra decode pass. Existing SSO callback sanitization runs first, and WebBrowser/Clerk continue receiving the original native event independently. This does not claim protection of hypothetical alternative consumers of the vulnerable base decoder.

TDD evidence: malformed-link regressions failed against the previous hook, and the literal-percent compatibility regression failed before the extra decoding pass was removed. All 22 final native-intent cases pass. `node --test scripts/deep-link-decoder.test.mjs` runs a bounded vulnerable-package control separately from the actual compiled hook/extraction diagnostic. The control timed out as expected; the guarded child completed in approximately 223 ms within the same two-second bound, rejecting actual extraction failures and preserving safe deeper encodings, Arabic and literal percent on cold/live calls. It does not force query-string parsing onto the installed Router path. The normal Jest integration tests use the actual Router parser. No device, provider, database or financial action is involved.

Fresh Android production export passed with 2,068 bundled modules and 2,052 mapped sources. `EXPO_NO_DOTENV=1 node node_modules/expo/bin/cli export --platform android --source-maps --output-dir dist/security-deep-link-2026-10-04-compatible --clear` produced the ignored Hermes bundle `entry-8fecf24e4a2a10e8ecf93f434c77c9be.hbc`. Its source map contains the exact current guarded native-intent source, Router's `URLSearchParams` parser and the unchanged vulnerable decoder. Typecheck and lint of all changed Mobile files passed. The full Mobile suite completed 455 suites / 2,533 tests passing before the literal-percent refinement; the final 22-case boundary suite then passed again. The full runner reported an open-handle warning and was stopped after its completed summary, so that run has no clean process exit. This offline export verifies bundling compatibility; it does not certify live environment configuration or a device/authentication acceptance run.

Upstream rates the decoder issue moderate and availability-only. A malicious link can stall decoding; this evidence does not establish remote code execution or financial/identity disclosure. [GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr).

The patched decoder release is 0.5.0 and is ESM; installed query-string 7 expects a callable CommonJS require. Blindly overriding 0.2.2 to 0.5.0 risks breaking linking and onboarding. No broad Expo/Clerk upgrade, dependency override or authentication refactor was performed. The native boundary mitigation does not patch the dependency, cover hypothetical alternate consumers of the React Navigation base parser, or certify web/native library security. Future Router upgrades must rerun the native integration and bounded diagnostic because the guard intentionally uses the installed extraction behavior.

Build-time findings remain relevant to trusted CI inputs and toolchain integrity; absence from shipped JavaScript is not dismissal of those findings. Existing isolated CI/timeout/secrets/container gates remain in force. This report does not assess native Java/iOS libraries or constitute a complete native SBOM audit.
