## Research applied

Android recommends48dp touch targets, meaningful control descriptions and readable foreground/background pairs. Preserve native affordances while correcting the layout. [Android accessibility guidance](https://developer.android.com/guide/topics/ui/accessibility/apps).

System insets must keep controls clear of system UI; that does not justify reserving duplicate empty space inside an already inset screen. [Android edge-to-edge guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge).

Normal text contrast is evaluated against4.5:1, with the standard's large-text exception kept distinct. Focus must remain visible around sticky or overlaid content. [W3C contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C focus visibility around obstructions](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).

Web targets must meet the applicable size/spacing requirement. Existing icon families should use consistent meanings, a named interactive wrapper and decorative SVGs that do not duplicate the label. [W3C target sizing](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [Lucide accessibility](https://lucide.dev/how-to/accessibility).

The repair sequence is layout/adaptation and semantic-theme hardening, followed by one bounded polish/verification pass. This report records the initial state; repair outcomes are appended after actual checks.

Overview commands retain visible names on compact screens, sit in a related action group and remain keyboard reachable. Narrow segmented controls use44px targets.
