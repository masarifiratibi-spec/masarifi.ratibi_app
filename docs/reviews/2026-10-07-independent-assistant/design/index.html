Review → design proposal

Two design directions

A. Conversation workspace · Recommended

A compact identity and capability banner, prominent question, recent chats, and answers with a financial summary and evidence. One stable shell carries pending, recovery, and previews. It directly addresses the observed lost question and absent history, avoids suggesting calculations before real data exists, and gives the keyboard room.

B. Financial overview dashboard

Lead with spending, budget and savings summaries, then place chat below. Useful for repeated monitoring, but duplicates Home and Reports, needs more reliable metadata than the current API supplies, and pushes conversation recovery down the screen. Retain this as a later optional insight entry point.

Interaction and accessibility specification

  • 48 × 48 dp minimum Android controls; visible labels and focus. Native builds must use semantic theme roles and actual system font scaling. This HTML large-text preview is illustrative and does not certify native accessibility.
  • Keyboard opens under a docked composer. Hide optional banners, keep the last turn reachable, cap input at five lines, scroll long drafts internally, and preserve scroll position. Android Back dismisses the keyboard first, then navigates. Newline remains newline; only the Send control submits.
  • Arabic navigation mirrors; currency/amount/date fragments use bidirectional isolation. History reads in chronological language order. Announce accepted, completed and failed once with a polite live region; do not steal input focus.
  • Evidence identifies period, scope, currency, source timestamp and limitations. “Saved records” is a fact label; forecasts are explicitly estimates. Missing data never becomes zero. Financial masking must cover user text, answer prose, evidence and previews.
  • Recovery uses the same accepted operation. “Check status” is for uncertain outcome; “Retry” is for known retriable failure. Editing creates a new intended question only after the old outcome is known. No fabricated progress percentage or online badge.
  • Preview confirmation is sample-only here. Production must show the full action-specific effects and current version, require explicit confirmation, disable duplicate submission and reconcile uncertain outcomes before permitting another action.
