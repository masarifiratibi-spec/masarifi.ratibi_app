# فحص صفحات الإصدار العامة — 2026-11-14 الرياض

النطاق: الخصوصية والشروط وصفحة طلب حذف الحساب بالعربية والإنجليزية، ومسار سياسة تحديث Android. لا نشر متجر، ولا إشعار أو بريد أو طلب حذف فعلي.

## النتيجة

- جميع الصفحات الست تعيد HTTP200 وHTML باللغة والاتجاه الصحيحين. روابط تبديل اللغة والخصوصية والشروط والحذف سليمة، وروابط أقسام المستندات تشير إلى معرّفات موجودة.
- فقرات الخصوصية والشروط المنشورة مطابقة لملفات JSON الحالية في worktree الصحيح بعد الإصلاح أدناه.
- أُجري تنقل فعلي في المتصفح بين اللغتين وصفحات المستندات والحذف، ومعاينة مرئية للخصوصية العربية والشروط الإنجليزية والحذف العربي. لم يظهر قص أفقي في فحوص DOM للصفحات المعاينة. لم تُستخدم محاكاة viewport للهاتف، ولا يدّعي هذا الفحص قبول كل مقاسات الشاشة.
- مسارات الصفحات دون `lang` تعمل، وHTTP يحوّل إلى HTTPS، وعينة `www` تحوّل إلى النطاق الأصلي مع الاحتفاظ بالمسار واللغة.
- `GET https://api.masarifiratibi.com/api/v1/meta/mobile-update` عام ويعيد HTTP200، و`Cache-Control: public, no-store`، والسياسة الدقيقة:

```json
{"schemaVersion":1,"enabled":false,"release":null,"storeUrl":"https://play.google.com/store/apps/details?id=com.masarifi.mobile"}
```

- جاهزية API بعد التغيير أعادت HTTP200. لم تُغيّر إعدادات تفعيل التحديث أو تُشغّل حملة أو تُنشر حزمة متجر.

## الخلل والإصلاح

فشل فحص المطابقة قبل الإصلاح فقط في فقرتي `storage` و`providers` للخصوصية العربية والإنجليزية: النسخة العامة ما زالت تصف Supabase كمزود القاعدة والملفات. المصدر المحلي كان مصححًا بالفعل ويصف PostgreSQL والتخزين الخاص على VPS؛ لم تُعدّل ملفات الموبايل أو Admin لهذه المهمة.

من Hostinger Web Console، قُرئت إعدادات Nginx الفعلية وحُدد إصدار الصفحات الثابتة. نُسخت ملفاته العامة الثمانية إلى إصدار منفصل، واستُبدلت الفقرتان في كل صفحة خصوصية فقط. بقيت الملفات الستة الأخرى مطابقة بالبصمات: الشروط والحذف باللغتين وملفا CSS.

- الإصدار السابق محفوظ: `/var/www/masarifi-public-legal-20261112/releases/d7190e3b17b2-56be4035ed81/site`.
- الإصدار النشط: `/var/www/masarifi-public-legal-20261112/releases/privacy-vps-20261114-211306/site`.
- إعداد الموقع: `/etc/nginx/sites-available/masarifi-public-legal-20261112`؛ تغيّر جذر الصفحات/الأصول فقط في المواقع الخمسة التابعة لهذه الصفحات. لم تتغير مسارات API أو TLS أو الحسابات.
- نسخة الإعداد السابق: `/etc/masarifi/selfhost/public-legal-privacy-before-20261114.conf` بصلاحية600.
- إيصال النجاح: `/opt/masarifi/selfhost/releases/2026-11-13/public-privacy-vps-repair-20261114.json` عند **2026-11-13 21:15:09 UTC / 2026-11-14 00:15:09 الرياض**، مع البصمات السابقة واللاحقة وإثبات بصمة الاستجابة العامة للصفحتين.

حُفظ الإعداد السابق واستُعيد تلقائيًا في محاولتي التفعيل الأوليين عند فشل فحص المحتوى ثم ظهور404. كشف التشخيص أن مجلد الإصدار الأب أُنشئ بصلاحية700؛ مُطابقتُه لصلاحية755 في الإصدار العام السابق وفحص قراءة جميع الملفات بحساب `www-data` عالجا السبب. بعد ذلك نجح `nginx -t` وإعادة التحميل والتحقق من البصمات العامة. لا حذف بيانات أو إعادة إنشاء لحاويات التطبيق.

## مسار حذف الحساب وحد القبول

الموقع العام الحالي **صفحة طلب بالبريد**، وليس نموذج حذف آلي أو تسجيل دخول. رابط `mailto:masarifi.ratibi@gmail.com?subject=Account%20deletion%20request` صحيح، والصفحتان تعرضان البيانات المعنية وحدود الحذف والاحتفاظ، وتميزان الطلب عن اكتمال الحذف. لم يُضغط رابط البريد أو يُرسل طلب، ولم يُحذف حساب أو يُختبر وصول البريد ومعالجته. فحص الصفحة لا يثبت تسليم البريد أو تنفيذ فريق الدعم للطلب أو دورة الحذف الكاملة.
