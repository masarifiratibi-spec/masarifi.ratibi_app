- العامل الحالي: `masarifi-requested-pdf-email-20261031-01` على هدف VPS، ويعمل ضمن `masarifi.scope=selfhost`.
- وجود SMTP host/port/username/password/from والمهل وحد المرفق تحقق دون طباعة قيم الأسرار أو Docker Env.
- المنفذ465، والمرسل مطابق لبريد المشروع `masarifi.ratibi@gmail.com`، وليس host تجريبيًا من نوع example/invalid/localhost.

## التنفيذ اللاحق وحد القبول

- [مرجع التجهيز المحلي](../../ops/selfhost/prepare-project-report.cjs) يرسم تقريرًا اصطناعيًا ويُركب MIME فقط؛ لا اتصال إرسال.
- [مرجع منفذ الإرسال المحلي المحروس](../../ops/selfhost/send-prepared-project-report.py). ثُبت منفذ بنفس الضوابط في مجلد الاختبار الخادمي باسم `send-prepared-project-report.py`، ونُفّذ فحصه دون وسيطات ثم `--send-once` مرة واحدة بطلب المستخدم. وجود intent حاليًا يمنع إعادة الإرسال؛ لا تشغّله مجددًا للتحقق من المنع.
- المنفذ يثبت المستلم وبصمات الملفات وهوية العامل ووحدة SMTP، ويحفظ intent حصريًا **قبل** الاتصال للإرسال. وجود intent يمنع محاولة ثانية حتى لو انقطع الاتصال أو كانت النتيجة مبهمة؛ لا يُحذف أو يُعاد تلقائيًا. لا يقبل قائمة مستلمين أو CC/BCC، ولا يستدعي العامل العام أو يغيّر إعداداته.
- بعد الإرسال المصرح به، قبول SMTP لا يساوي وصول الصندوق؛ يلزم رصد الرسالة في بريد المشروع ومطابقة Message-ID والمرفق. لا يُعلن نجاح تسليم فعلي من `verify()` أو من streamTransport.
- هذا الاختبار يعزل renderer وSMTP الفعليين؛ لا يثبت وحده دورة الطلب الموثق عبر API ثم snapshot/storage/worker ومشاهدة الحالة داخل التطبيق. تبقى تلك دورة قبول منفصلة ببيانات اختبار وهوية مصرح بها.

لا تغيير أسرار أو إعدادات إنتاج، ولا إعادة تشغيل عامل، ولا إرسال لأي مستلم سوى بريد المشروع المحدد، ولا إشعار أو نشر متجر.
